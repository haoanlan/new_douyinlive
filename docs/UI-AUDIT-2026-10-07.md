## 一、P0 —— 用户直接踩得到

### 1. 搜索页返回即清空（实测复现）
**现象**：在「信息查询」输入关键词查询成功（实测：`林语` → “5 个匹配用户 / 18 个参与场次 / 1,654 累计钻石”，列表有结果），点进 `场次详情` 后按浏览器后退：
```
输入框 value: "林语" → ""      汇总: 5 个匹配用户 → 0 个匹配用户
列表: 有结果        → 回到「开始查询」空态
```
**原因**：`search` 是 8 页里**唯一没有 `keepAlive`** 的列表页，走 `art-page-content/index.vue:34` 的 `v-if="!route.meta.keepAlive"` 分支，离开即卸载；关键词/结果/排序/范围全在内存 `ref`（`search/index.vue:338-354`）。
**证据**：`router/modules/douyin.ts:55-59`（无 `keepAlive`）、`art-page-content/index.vue:19-36`。
**改法**：① 给 search 加 `keepAlive: true`（与其余 6 页一致）；② 更彻底：把 `q / sort / scope` 双向绑定到 `route.query`（`router.replace`），既能返回保留又能分享链接。查询会调抖音接口、成本高，重复查询尤其浪费。

### 2. 所有页面的滚动位置每次归零（实测复现）
**现象**：`#app-main` 是真正的滚动容器（实测 `overflow-y: auto`，内容 2106px / 视口 950px）。滚到 900 后：
```
切到别的页     → 0
切回来（hash） → 0
浏览器后退     → 0      （dashboard 是 keepAlive 页，组件被缓存了也一样归零）
```
**原因**：`router/index.ts:9-12` 没有 `scrollBehavior`（对自定义容器也无效），而 `router/guards/afterEach.ts:13-14` 在**每次**导航后无条件 `scrollToTop()` → `#app-main.scrollTop = 0`。
**改法**：列表页在 `onDeactivated` 存 `#app-main.scrollTop`、`onActivated` 还原；或 `afterEach` 里区分"后退/前进"与"新导航"，只在后者回顶。这是长列表（rooms 卡片、sessions 第 3 页）最容易感知的体验损失。

### 3. 趋势页首屏「整屏空白 → 空态 → 内容」两次跳（实测复现）
**现象**（首次加载逐帧采样 250ms，`#app-main` 内容高度 / 正文可见字数 / 是否空态）：
```
+250ms  h=950  txt=0    loading=true   ← 整屏没有任何文字，只有按钮转圈
+500ms  h=950  txt=95   empty=true
+750ms  h=1846 txt=257  empty=false    ← 内容整块插入，高度 +896px
```
**原因**：`onMounted` 自动选中"场次最多的房间"（`trends/index.vue:572-575`、`:619-621`）把 `v-if="!selectedHosts.length"` 的引导卡（`:96-102`）顶掉，此时 `hasData` 仍为 false，而占位分支又写成 `v-else-if="!loading && !queryError"`（`:270`）→ 三个分支全不成立。
**改法**：内容容器加 `v-loading="loading"`；引导卡条件改 `!selectedHosts.length && !loading`；空态一律加 `!loading`（可照抄 `search/index.vue:112` 的写法）。

### 4. trends 图表不随视口自适应，1024/1280 下被裁（实测）
**现象**：1024×768 视口下 `documentElement.scrollWidth === 1024`（不产生横向滚动），但图表容器与 canvas 的 `right = 1443` —— 图表按首次渲染的宽度画完就不管了，超出部分被父容器裁掉（视觉上右侧数据被切）。1500px 视口下正常。
**证据**：`views/douyin/trends/index.vue` 无 `ResizeObserver`/`window.resize` 监听（旧评审 P2 也提过 `h-72` 无 resize）。因为 5 个页面都 keepAlive，窗口缩小后再切回来也不会重绘。
**改法**：echarts 实例加 `ResizeObserver` → `chart.resize()`；或在 `onActivated` 里 resize。

## 二、P1 —— 排版 / 动效 / 跳转的系统性问题

### 5. 5/8 页没有路由切换动效，另外 3 页有（实测）
`dashboard / rooms / sessions / trends / status` 都标了 `keepAlive: true`（`router/modules/douyin.ts:20,28,39,50,67`），走 `<KeepAlive>` 分支，而**该分支外面没有 `<Transition>`**（`art-page-content/index.vue:19-26`）；只有 `search / detail / profile` 走 `:29-36` 的 `<Transition :name="pageTransition">`（默认 `slide-left`）。
实测切页头 400ms 内的动画：
```
dashboard → rooms（都 keepAlive）：views=1 opacity=[1] 动画只有卡片进场 dy-card-in   ← 硬切
rooms → search（目标非缓存）    ：views=1 opacity=[0.22 → 0.74 → 0.95 → 1] + tr:opacity/transform 250ms
```
**影响**：`router-transition.scss` 对主菜单 5 页属于死代码；用户感知是"菜单间跳转很生硬，点搜索结果反而有动画"。
**改法**：给 KeepAlive 分支套同一个 `<Transition>`（若要避免缓存页重播动画，可只在首次激活时启用），或统一取消过渡改硬切 + 内容级进场动画。

### 6. 有过渡时新旧两页同时占文档流（实测）
```
search → detail/236：+60ms views=2 opacity=[1, 0]  anims=tr:opacity@175(离开) + tr:opacity@250(进入)
                    +180ms views=2 → 之后才 views=1
```
`<Transition>` 未设 `mode`，默认"进入与离开同时进行"（离开 175ms、进入 250ms）。`#app-main` 是滚动容器，重叠期间滚动内容高度接近翻倍 → 滚动条跳、位置漂移；`slide-*` 只位移 15px，观感是"新页从旧页下面顶上来"。
**改法**：`mode="out-in"`（代价是总时长 175+250ms），或过渡期间给 `.art-page-view` 加 `position:absolute; inset:0` 叠放（当前全项目没有一条 `.art-page-view` 规则）。
**附带**：`router-transition.scss:33/66/73` 的 `will-change: opacity, transform` 作用在整页子树上，进出场各促升一个全页合成层（类会随过渡移除，不算滥用，但低端机有栅格化尖峰）。

### 7. 停在其他页时，被缓存的页面仍在后台轮询（实测）
停在 `search`（非 keepAlive）20 秒，仍收到：
```
/api/status ×2            （间隔 10s ← dashboard 的 setInterval）
/api/service/status ×3    （间隔 8s  ← status 页的 setInterval）
```
三页都只在 `onUnmounted` 清定时器，而 keepAlive 页切走时**不会 unmount**（`dashboard:450-458`、`sessions:436-440`、`status:775-787`）。`rooms` 是正确实现（`rooms/index.vue:749-754`：`onActivated` 起、`onDeactivated` 停 + 可见性判断），且注释里明确写了"只在该页可见时轮询"——另外三页没跟上。
**改法**：三页统一改用 `onActivated / onDeactivated`（sessions 是 `isHideTab`，标签关不掉，尤其需要）。

### 8. 首屏加载高度跳变：dashboard 先撑高再收缩 393px（实测）
```
dashboard：+250ms h=2499（空态 + loading 蒙层先把 5 个区块撑起来）→ 稳定 2106   = 收缩 393px
trends   ：见 P0-3（+896px）
status   ：h 稳定，但正文从 391 字直接变成 1902 字（整块替换）
rooms / sessions / search：首屏即稳定（内容不足一屏）
```
**根因**：8 页**没有任何骨架屏**（全项目 `el-skeleton` 0 处），一律"先渲染 `el-empty`，数据回来整块替换"。
**改法**：给每块固定 `min-height` 或上 `el-skeleton`（依赖已装，无需新增）；空态判断统一加 `!loading`。

### 9. 点按目标小于 24×24（WCAG 2.5.8 AA，实测）
| 页面 | 元素 | 实测尺寸 |
| --- | --- | --- |
| dashboard | 列表行「详情」按钮（8 个） | **30×18** |
| status | 「运行日志（18 行）」折叠头 | **116×16** |
| trends | `el-tag` 关闭按钮 | 14×14（有 aria-label） |
| trends | 时间范围 radio | 58×**22** |
（`el-button--small` 的高度是模板/EP 决定，但 18px 高在触屏上确实难以命中。）
**改法**：给这些小按钮加 `min-height: 24px`（或 `py-1`）+ 触屏 `tap-highlight`；折叠头改 `py-2` 让它至少 32px。

### 10. 失败态仍是"空态插图"+ 把 64 字符内部标识抛给用户（实测）
用**主播**的 sec_uid 打开 `/douyin/profile/<sec_uid>` 时页面显示：
```
「未找到该用户的记录（sec_uid: MS4wLjABAAAAvS6SMG2j7WPToijXWwJncVFg38xn6vIW2rg16_Qqj0kSQY56eiUSBmBBjP8l_Qlw）」 + 重试
```
**先澄清一个易误判的点**：`GET /api/users/:secUid` 查的是 `gifts.user_sec_uid`（**观众/送礼者**），不是主播，所以主播 sec_uid 返回 404 是**正确行为**；画像页的唯一入口在 search 结果（`search/index.vue:185`），走的是观众 sec_uid。**不是页面坏了**。
**真问题**：① 错误用 `el-empty` 插图承载（8 页里只剩它没用共用 `QueryErrorState`），② 把内部字段名与 64 字符串直接给用户看（`profile/index.vue:284-287`），③ 该分支下 `v-loading` 不在树上，点「重试」没有任何进行中反馈。
**改法**：改用 `QueryErrorState`（`:retrying="loading"`）、文案改「未找到该用户的互动记录」并去掉 sec_uid。

### 11. detail 失败无任何反馈，刷新按钮无 pending（源码确定）
`detail/index.vue:761-771` 的 `refresh()` 只有 `try/finally`、没有 `catch`（失败是 unhandled rejection），`onMounted` 也未 await；8 页里只有 detail 既没有错误态、刷新按钮也没有 `:loading`（`:37`），连点会并发请求。
**改法**：加 `queryError` + `QueryErrorState`（组件已存在），按钮补 `:loading/:disabled`。

### 12. sessions 单条删除失败会静默（源码确定）
`sessions/index.vue:395` 的 `await deleteSession(...)` 没有 try/catch，失败也会执行 `ElMessage.success('已删除')`；而同页批量删除（`:412-418`）却是"逐条 catch 后仍提示已删除 N 场"——同一操作两种错误策略，用户无法相信界面。
**改法**：包 try/catch + `apiErrorMessage(e, '删除失败')`，失败不刷新列表、不改选择集；批量删除汇总失败条数。

### 第一轮踩到的坑（值得记住）

- **不要用 `popstate` 事件给"后退/前进"打标记**：vue-router 自己也在监听 popstate，浏览器会在**每个监听器返回后做一次微任务检查**，于是 vue-router 的导航可能在我们的监听器之前就跑完 `afterEach`（标记还没置位就被消费）→ 位置永远恢复不了。改用历史条目序号：vue-router 给新条目写 `position = 上一个 + 1`（replace 保持原值），所以「新位置 ≠ 上次位置 + 1」就是前进/后退。

## 十、第三轮：暗色专项（已实测）

**为什么前两次切不过去**：模板的暗色 = `<html class="dark">`（`config/index.ts:44-47`），而持久化里 `systemThemeMode` 若为 `auto`，`initializeTheme()`（`hooks/core/useTheme.ts:129-159`）会用 `usePreferredDark()` 覆盖 `systemThemeType` —— 无头环境系统偏好是 light，所以只把 type 改成 dark 完全没用。正确姿势：Playwright context 给 `colorScheme: 'dark'`（等价于系统"深色外观"）并让 mode 保持 `auto`。

**工具**：`scripts/ui-audit-dark.js`（可复用：切暗色 → 逐页扫对比度 → 专项探针）。一个必须注意的坑：**oklch→sRGB 要自己算** —— Chrome 的 `ctx.fillStyle` 会把 `oklch(...)` 原样回读，当成 rgb 解析会得到 `rgb(1,0,256)` 这种垃圾值（第一版就是这么错的，报出 1.01:1 的假阳性，差点又写进报告）。

**实测结果（1500×950，7 页 = 6 个主页面 + 场次详情）**：

| 项 | 实测 | 结论 |
| --- | --- | --- |
| 全页文字对比度 | 采样 **3311** 个节点，未达标 **10 处 → 0 处**（修后） | 修前 10 处全是名次徽章 |
| 名次徽章第 1 名 | `text-amber-600` 被语义色收口改成 `rgb(251,191,36)`，配 `bg-amber-100` = **1.5:1**（需 4.5） | 真 bug，已修 |
| 名次徽章第 3 名 | `oklch(0.646 0.222 41.116)` on `rgb(255,237,212)` = **3.14:1** | 真 bug，已修 |
| 名次徽章第 2 名 | slate 组合通过 | **推翻**早先的 1.01:1（那是解析错误） |
| 焦点隔离环 | `outline: rgb(255,255,255) 3px` | **推翻原判断**：暗色下白色环清晰可见，不是问题 |
| status 进度条轨道 | `rgb(54,54,55)`（卡片 `rgb(22,22,24)`） | **推翻原判断**：写死的 `rgb(240,240,240)` 没落到这个元素上 |
| `.mon-chip` / `.mon-kv__label` | 8.27:1 / 5.7:1 | 达标 |
| 暗色语义 token | `--dy-text-primary #e3e3e8`、`--dy-text-secondary #ababba`、`--dy-text-muted #8f8fa3`、`--default-box-color #161618` | 达标 |

**修法**：`rankClass()` 不再返回 Tailwind 固定调色板，改为成对的 `.dy-rank--1/2/3`；`douyin-motion.scss` 给出浅色（amber-800 on amber-100 等，6.4–8.4:1）与暗色（亮字 + 半透明同色底，8–10:1）两套值。

**复验**：暗色 7 页 **0 处未达标**；浅色回归 `ui-regression` **9/9**（采样 478 处 0 未达标）。

**仍读不到的**：ECharts 画在 canvas 里的文字色（`#8a94a6`）、词云（`#888`）、暗色下悬停阴影的实际观感 —— 要看图或读 canvas 像素才能判断。
